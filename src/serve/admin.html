长上下文淘汰 (L3)

⚠ 已开 --l3-evict 但未开 P3 门：--prefix-kv 会被静默打掉，多轮追问将全量重算 prefill。建议开启上面这项。
0 = prefill 后总是淘汰；N>0 = 上下文达到 N tokens 才启动淘汰（实测口径 128，越小越白付驱逐开销）。
路径可填 eMMC 挂载点（如 /mnt/emmc/kv_l3.bin）；最大大小 0 = 不限制。
每用户独立缓存文件，闲置超 TTL 分钟自动删除（0 = 不清理）。
开 --l3-evict 时务必同时开上面那项 P3 门，否则 KV 前缀复用会被静默打掉。

注意事项（三轨互斥，只有精确轨可复现）
1. 精确轨 = 位级一致（A 等同于 C），可与任意参考实现逐位对拍；s16 与 ACTQ 都是近似轨，输出与精确轨不逐位相同。
2. s16 与 ACTQ 互斥且 s16 优先（引擎内命中 s16 时强制关掉 ACTQ）。
3. s16 轨目前只有 x86 内核，板端 ARM 是「恒 0」安全桩：在板端选它等于精确轨，不会有任何提速，也不会报错。
4. ACTQ 走 int8 激活量化，误差约 0.4%，实测贪婪解码在约 23 token 后开始漂移（长文本 t 约 24 起）。
5. ACTQ 生效还需三个条件同时成立：模型按 --wmode q4 转换、专家几何成立（ff 能被 ne 整除且 4 行对齐）、ARM 上编译期具备 NEON dotprod。
6. EP（专家并行 / 分布式专家抽取）场景必须留在精确轨：main.c 会强制 ACTQ16=0，且 ACTQ / ACTQ16 都会让 M1/M2 位级对拍变成假对拍。
7. 「批式 prefill」与轨道相互独立：精确轨下它也是位级一致的跨 token 融合（默认开，无精度损失）；ACTQ 轨下它改走 int8 近似核。
8. 本卡片的 env 在进程启动时读取一次：改完需「保存配置」并重启引擎才生效。
9. 拿不准就留精确轨：板端 30B 精确轨 prefill 已从约 37 s 降到约 7 s（5.3 倍），代价是仍比 ACTQ+批式慢约 2.3 倍。
仅对 q4 专家生效（非 q4 自动回落逐 token）；标记「保存」后需重启引擎生效。参数口径见《核心性能参数配置注意事项.md》。
