## 0. 入口与口径（先冻结再采数）

### 0.1 引擎多模态入口（仅 serve 可达）

- **CLI 的 `--multimodal`/`--image`/`--video` 是死标志**：`src/main.c` 里 `run_multimodal`/`n_images`/`img_paths` **只赋值、从不使用**（[main.c L4498-L4501](../src/main.c#L4498-L4501)、[L4702-L4707](../src/main.c#L4702-L4707)）⇒ **CLI 无法跑图文推理**。
- **唯一可用入口 = serve**：`POST /v1/chat/completions`，`messages[].content` 传 **parts 数组**，`{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`（[vllm_server.c L2170-L2199](../src/serve/vllm_server.c#L2170-L2199)）；解码用 stb_image（png/jpg/bmp/webp）。另有客户端预处理的 `vision_tokens` 直传路径（跳过 ViT）。
- 请求须带视觉部分才会走多模态 prefill（`detect_media` 命中，[L2871-L2872](../src/serve/vllm_server.c#L2871-L2872)）；服务端须加载了含 ViT 的 VQF，否则 400。

### 0.2 口径

- governance=`performance`；线程 **t4**（`VLLM_THREADS=4 OMP_NUM_THREADS=4`）；`--serve --auto-load --port 8080`；`temperature=0`、`top_p=1`、`stream=true`、`max_tokens=64`；**不传 `enable_thinking`**（默认；理由见 K-BENCH-019 附录 A：VL-Instruct 不接受引擎手写的 no-think 后缀）。
- 每档**先预热**（一轮纯文本 "你好" + 首张图触发的 ViT/首次页入），逐图**实测**；**单会话读数**（依 `session_local_ab_caliber`，不跨会话互比）。
- `VLLM_MMDBG=1` + `stdbuf -oL` 采集 ViT 分步日志与 `[VIS] Image encoded: WxH → P patches → N visual tokens`。

### 1.3 延迟构成（关键）

- **`prefill_ms` 不含 ViT**：`wall ≈ ViT 编码 + prefill + decode`。反算 **ViT ≈ 74–86 s/图**（`wall − prefill − tpot×gen`），占单次端到端 **≈85%**。
- `[VIS]` 分步（`VLLM_MMDBG`）：2B ViT 24 层，逐层 `d1_qkv≈0.23s + attn≈1.56s + d2a≈1.64s + d2b≈2.35s ≈ 5.8 s/层`；`preprocess`/`patch_embed` 仅 0.01/0.47 s ⇒ **ViT 成本几乎全部是 2262–2304 patches 的 O(n²) 全注意力**（2B/8B 均无窗口化）。
- 纯文本对照：prompt 39 tok 的 prefill **0.15–0.53 s**（与 K-BENCH-019 一致）⇒ **图文请求的端到端成本 = ViT 主导，而非 LLM prefill**。

> ⚠️ **指标口径存疑（登记待核）**：`[VIS] Image encoded` 报 551–576 visual tokens，而 metrics 的 `prompt_tokens` 比纯文本模板多 **≈1104**（1143 − 39）≈ **2×(visual tokens)** ⇒ `prompt_tokens` 似对图文轮**重复计数**（或把视觉 pad 与多模态 prefill 行各算一次）。**本项不据此下结论**，KV 占用以 `[VIS]` 报告为准（551–576）；建议后续核对 metrics 实现。

## 3. 决定性定位实验（区分「引擎 8B 路径缺陷」vs「8B VQF 文件缺陷」）

**方法**：用 256×256 纯色 BMP（红/绿/蓝）——patches 仅 256、visual tokens 64 ⇒ **ViT 秒级**，可快速反复；加真实斑马图。

| 载体（VQF） | 红 | 绿 | 蓝 | 斑马 | 结论 |
|---|---|---|---|---|---|
| 2B **新**（`/mnt/VQF/2b`，2026-10-10 转） | `红色`✓ | `绿色`✓ | `蓝色`✓ | `斑马`✓ | **4/4 全对** |
| 2B **旧**（`/mnt/emmc/Modl/Qwen3-VL-2B-q8fix`，**2026-09-14** 转） | `红色`✓ | `绿色`✓ | `蓝色`✓ | `斑马`✓ | **4/4 全对** |
| 8B（`/mnt/VQF/8b`，**2026-09-18** 转，md5 `f8ca1002…`） | `红色`✓ | `蓝色`✗ | `蓝色`✓ | `海豹`✗ | 2/4 |
| 8B（`/mnt/emmc/Modl/8b-q4`，**2026-09-24** 转，md5 `8a909a33…`） | `红色`✓ | `蓝色`✗ | `红色`✗ | `海豹`✗ | 1/4 |

**判读**：

1. **引擎视觉通路本身正确**：**两份互相独立**的 2B VQF（含 **9-14 旧转换**）在同一引擎、同一批请求下**全对**（纯色 + 真实斑马）⇒ 视觉编码 → 视觉 token 注入 → LLM 解码链路无缺陷；也**排除"旧转换器有 bug"**（旧 2B 通过）。
2. **故障专属 8B**：两份**不同 md5** 的 8B VQF 均失败（且红/蓝可部分读出 ⇒ 视觉未完全失效，是**特征被部分破坏**）。
3. **8B 与 2B 的差异几何**（引擎侧唯一的 8B 特有面）：
   - **ViT `head_dim = 72`**（2B 为 64）；源码注释已记 8B/32B 的 `head_dim=72` 曾致栈越界，2026-09-07 以 `VVIS_ATTN_ACC 16→32` 修（[vllm_vision.c L298-L302](../src/model/vllm_vision.c#L298-L302)）；
   - **`vis_ffn = 4304`**（非 32 倍数，Q8 需 pad 到 4320；2B 为 4096 免 pad）；
   - ViT 27 层 / hidden 1152 / out_dim 4096 / ds_idx `[8,16,24]`。
4. ⇒ **故障点在 8B 专属几何的引擎视觉路径，或两份 8B VQF 的视觉权重本身**；二者**当前无法区分**，因板上**无 Qwen3-VL-8B 源权重、无 8B mmproj 参照**（无法重转/对拍）。

### 3.1 VQF 结构审计（排除"文件结构损坏"）

- **8B 头**：`[VQF] legacy 41-field VQFArch header detected …, normalized`（[vqf.c L189-L210](../src/model/vqf.c#L189-L210)）——旧头仅为 arch 尾部 **MoE 4 字段**缺失 + `data_offset/file_len` 错位 16B；**arch 前 41 字段（含全部视觉元数据）新旧一致** ⇒ **视觉元数据不受旧头影响**。
- 逐字段核对（自写解析器）：`has_vision=1, vis_depth=27, vis_hidden=1152, vis_heads=16, vis_ffn=4304, vis_patch=16, vis_merge=2, vis_out_dim=4096, vis_max_pos=2304, vis_ds_count=3, vis_ds_idx=(8,16,24), mrope_sections=(24,20,20)` —— **全部正确**。
- 张量目录（41 tensors）几何**逐项自洽**：`v_q8_qkv 27×3981312(=3·1152²)`、`v_q8_proj 27×1327104`、`v_q8_fc1 27×4958208(=1152·4304)`、`v_q8_fc2 27×4976640(=1152·4320 已 pad)`、`v_patch_embed 1769472(=3·2·16·16·1152)`、`v_pos_embed 2654208(=2304·1152)`、`v_qkv_bias 27×3456`、`v_merger_f1w 21233664(=4608²)`、`v_merger_f2w 18874368(=4608·4096)`、`v_ds_* 3×…` ⇒ **结构与文档/代码假设一致**。
- 文件身份：`/mnt/VQF/8b/qwen3vl8b.q4.vqf` 与 `/mnt/VQF/8b/serve/model.vqf` md5 相同（`f8ca1002311e3790778006add2a8057f`）；`/mnt/emmc/Modl/8b-q4/model.vqf` 为另一产物（`8a909a33bfda4b73bca8678dbd6a70cc`）。

> 结论：**不是文件结构/元数据问题**，也**不是转换器版本问题**（旧 2B 通过）；故障面收敛到 **8B 视觉数值/引擎 8B 路径**。

## 4. 2B 图文延迟汇总（供在线预算参考）

| 项 | 值 |
|---|---|
| ViT 编码（768px 真实照片，~2260 patches） | **≈74–86 s**（2B）/ ≈102–120 s（8B） |
| LLM prefill（~1143 tok） | 14.5–15.8 s（2B）/ 49–53 s（8B） |
| 端到端（gen≤3） | **≈89–101 s**（2B）/ 152–171 s（8B） |
| 纯文本对照（39 tok） | 0.15–0.53 s（2B） |
| 小图（256px，256 patches） | 端到端 **6.4–7.0 s**（2B）/ 11.7–13.7 s（8B） |

- **端到端由 ViT 主导（≈85%）**；ViT 成本随 patches **近似 O(n²)**（全注意力）⇒ 缩图/降 patches 是最直接的加速面。
- 2B 的 5 图 `visual tokens` 稳定在 550–576（≈patches/4）⇒ 每次图文请求约 **+550 KV 行**。

## 5. 结论

1. **引擎多模态入口只有 serve**（CLI `--multimodal/--image` 为死标志，[main.c L4702-L4707](../src/main.c#L4702-L4707)）；走 `image_url` base64 data URL，stb_image 解码。
2. **2B（Qwen3-VL-2B）视觉可用**：5 张真实照片 **严格 4/5、语义 5/5**；无图对照 **0/5**（去掉题面泄题项）⇒ 视觉通道真实生效。
3. **8B（Qwen3-VL-8B）视觉不可用**：5 张**全部答错**（0/5），且对纯色 BMP 也只能读出红/蓝中的一部分；**两份独立 8B VQF 均复现**。
4. **根因定位（证据链）**：同一引擎下，**两份独立 2B VQF（含 9-14 旧转换）全对**（含纯色与真实图）⇒ **引擎视觉链路正确、且排除旧转换器 bug**；8B 故障面 = **8B 专属几何（ViT `head_dim=72` / `vis_ffn=4304` 非 32 倍数）的引擎视觉路径** 或 **两份 8B VQF 的视觉权重本身**。**§6 已进一步排除**：VQF 结构/步长/NaN/头伪造/转换器版本/引擎代码漂移，并**找到+修复了一处真实引擎缺陷**（非 2 的幂 `v4n` 归约漏项），但该修复**未改变** 8B 输出 ⇒ **主因仍未闭合（H1 权重语义 vs H2 另一处引擎算法，二者当前不可区分）**。**VQF 头部与张量几何已逐项核对无误** ⇒ 非结构/元数据问题。
5. **端到端成本 = ViT 主导（≈85%）**，非 LLM prefill（2B prefill 14.7 s vs ViT ~80 s）；ViT 全注意力随 patches 近似 O(n²)。
6. ⚠️ **指标口径存疑（登记）**：metrics `prompt_tokens` 对图文轮似**重复计数**（约为 `[VIS]` visual tokens 的 2×）。
7. **2B 图文识别强化复测（§7）**：11 张真实照片 **语义识别 11/11**（严格 10/11，唯一失分是"要求英文答中文"的指令跟随）；**无图对照 0/11**、**幻觉否定 3/3**、**重复一致 3/3** ⇒ **2B 图片识别无功能性问题**（§6.2 的修复实测对 2B 无影响）。

### 未覆盖（诚实登记）

1. **8B 视觉的裁决实验（未做，用户决定"先不做了"）**：候选见 §6.3 —— **(a)** 独立 Python 视觉塔参考（读同一 VQF 权重）+ 引擎 token 转储，先用 2B 校验参考；(b) 重下 Qwen3-VL-8B 源权重（~17 GB）用当前转换器重转复测。**板上既无 8B 源权重、也无 mmproj**，故两者都需额外投入。
2. 分辨率扫描（ViT 成本 vs patches 的定量曲线）、更低分辨率下的质量。
3. 视频（`video_frames` 多帧）路径未测；`vision_tokens` 客户端预处理路径未测；**prefix-KV 多模态复用**（P4）未测。
4. 多图同请求（`n_regions>1`）、像素级 OCR/计数类任务（本项只做了"是什么"级判别）。
5. 全部为**单会话读数**；无跨会话/跨进程重复。

## 6. 8B 视觉失效排查〔2026-10-10 追加〕

**背景**：§2/§3 已定位「8B 含图 0/5、2B 4/5」且故障**专属 8B**。本节记录代码级排查的证据链、已排除项、**找到并修复的一个真实引擎 bug**，以及仍未闭合的开放项。

### 6.1 证据链与已排除项

| 假设 | 判定 | 证据 |
|---|---|---|
| 8B VQF **结构/步长**损坏 | **排除** | 41 张量逐项 `per_layer == exp`（含 `v_q8_fc2` 的 4320 pad 步长 5287680）；目录/偏移自洽（数据指针 = `base + e->offset`） |
| 8B 视觉权重 **NaN/全零/尺度异常** | **排除** | Q8 逐层（27 层）`std=0.015–0.029`、`amax=0.06–0.2`、`nan=0`、层间平滑；F32 张量量级合理（如 `v_norm1_w` ≈1、`v_fc1_bias` ≈ −1.2…−2.5） |
| 头被**手改**（伪造视觉元数据） | **排除** | `serve/model.vqf.hdr.bak`（9-15）与当前头**仅 `max_seq`（8192→20480）不同**，视觉字段逐字节相同 |
| **转换器版本** | **排除** | `vqf_convert/src/vqf_vision.c` 自 **2026-09-11** 起无改动（`git log`），且同一转换器产出的 2B（10-10）通过 |

### 6.2 找到并修复的引擎 bug（真实，但**不解释**本症状）

`vvis_vit_attn_block`（[vllm_vision.c L324-L339](../src/model/vllm_vision.c#L324-L339)）里 NEON 累加器二分归约：

```c
for (int w = v4n / 2; w >= 1; w >>= 1)
    for (int i = 0; i < w; i++) acc[i] = vaddq_f32(acc[i], acc[i + w]);
```

只在 `v4n` 为 **2 的幂**时覆盖全部 `v4n` 个 float32x4 累加器：

- 2B `vis head_dim = 1024/16 = 64` → `v4n = 16`（2⁴）⇒ 全覆盖
- 8B `vis head_dim = 1152/16 = 72` → `v4n = 18` ⇒ **静默丢掉 acc[8]、acc[17]** ⇒ 注意力点积**漏掉 head 维 32–35 与 68–71**

（本地数值模拟：`v4n=18` 覆盖 16/18、缺失 idx=[8,17]；`v4n=16/8/32` 全覆盖。）

**修复已落地并保留**：改为「2 的幂时与旧二分树**逐位一致**；非 2 的幂把**奇数尾项**折回 acc[0]」：

```c
for (int nacc = v4n; nacc > 1; ) {
    int hf = nacc >> 1;
    for (int i = 0; i < hf; i++) acc[i] = vaddq_f32(acc[i], acc[i + hf]);
    if (nacc & 1) acc[0] = vaddq_f32(acc[0], acc[nacc - 1]);
    nacc = hf;
}
```

- 模拟验证：`v4n ∈ {17,18,20,36}` 均 **100% 覆盖**；`v4n` 为 2 的幂时操作序列与旧实现一一对应 ⇒ **2B 逐位无回归**。
- 板端 `build_rk3588.sh` rc=0（增量 3 s）；旧二进制备份 `vllm_kestrel.bak_pre_vattnfix`。

> ⚠️ **诚实披露**：该修复经复测**未改变** 8B 观测输出（合成图仍 红✓/绿✗蓝/蓝✓/斑马✗ 海豹）⇒ 8/72 维丢失不足以翻转 argmax。**该 bug 是真实缺陷（顺带修复），但不是本症状主因。**

### 6.3 仍未闭合（开放项）
