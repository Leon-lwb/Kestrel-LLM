## 3. 机理定位（G0 核心：用真实专家热度做分配仿真）

### 3.1 先把表观间隙的两处**口径失真**扣掉

| 失真 | 方向 | 幅度 |
|---|---|---|
| 探针用 **m=16 均匀**（128×16 = 2048），真实 `Σm_e = nsel = 1888` | 探针 MAC **高估** | **+8.5%** |
| 探针**不含**负载不均（均匀 m 天然均衡） | 探针时间**低估** | 见 §3.3 |

⇒ 扣掉 MAC 口径：`14.40 / 1.085 = 13.27 GMAC/s`（同口径）。

### 3.2 数据来源：**真实专家热度**（不是合成分布）

板端 `/tmp/heat30b_256.txt`（K-L0-003 的 246-token 采样，48 层 × 128 专家计数）。每层：

| 统计量 | 值 |
|---|---|
| 每层 token-rank 合计 | 484160（= 246×1968，含已登记的 nb 倍放大；**比值不受影响**） |
| 每层 `m_e` 均值 | 3783 |
| 每层 `m_e` **max** | **26960** |
| **max / mean** | **7.19（中位）** ← **强偏斜** |

### 3.3 分配仿真（4 线程，专家为不可分单元）

`vllm_tp_parfor` 是**静态连续切分**（`base=n/nt, rem=n%nt`，[vllm_tp.c#L404-L413](../src/core/vllm_tp.c#L404-L413)）。exp-major 下 idx = `e*(d>>2) + rg` ⇒ 线程 t 恰好拿到**连续的 32 个专家**。故线程工作量 ∝ 其 32 个专家的 `Σm_e`。

**负载不均比 `max/mean`（1.000 = 完美均衡）：**

| 方案 | 中位 | 说明 |
|---|---|---|
| **① 当前：exp-major 连续切分** | **1.243** | 慢线程比均值多干 **24.3%** |
| ② 交错（round-robin，`e ≡ t mod 4`） | 1.220 | **几乎无效**（1.005×）——热专家只落一个线程 |
| ③ 蛇形（按 `m_e` 降序 zigzag） | 1.035 | 有效但要打破朴素排序 |
| **④ LPT + 容量约束（每桶恰好 32 个专家）** | **1.000** | **完美均衡** |
| ⑤ LPT 无容量约束（下界参考） | 1.000 | 与 ④ 同值 ⇒ **无需打破「32 专家/线程」约束** |
| ❌ 按 `m_e` 降序**连续**切分 | 2.875 | **更差**（把热专家堆在一个线程） |

⇒ **机理确认**：残余间隙中**可归因于负载不均的份额 = 1.243×**；且**修复方案 = LPT 装桶**，不需要改变切分粒度。

### 3.4 归因分解（把 §3.1 的口径失真与 §3.3 的不均都扣掉）

```
探针（均匀 m=16，表观）           14.40 GMAC/s
  ÷ 1.085（MAC 口径归一）          13.27 GMAC/s
  ÷ 1.243（真实 m_e 分布下的不均）  10.68 GMAC/s   ← 与引擎同口径的"可解释上限"
引擎实测                            8.68 GMAC/s
⇒ 残余未解释间隙                    1.23×          ← 属"引擎环境"，本项不解释（登记）
```

## 4. 可达上界（**反算，须披露推导式**）

| 档 | 推导式 | 预计 |
|---|---|---|
| **dn 段** | `1 − 1/1.243` | **−19.5%** |
| **prefill** | `16410.7 × 0.1954 = 3207 ms` ⇒ `25550 − 3207` | **≈22343 ms ⇒ −12.6%** |

> ⚠️ 口径披露：
> - 上表是**仿真上界**（假设"慢线程是唯一关键路径"且轻线程有算力余量可吸收），**不是实测**；
> - dn 同时受 DRAM（约 500 MB/s ≪ 12 GB/s）与延迟约束 ⇒ 若实际为**延迟受限**，实测收益会**低于** −19.5%；
> - 探针残留的 **1.23× 未解释间隙不在本项范围**（需另测）。

## 7. 判定敏感项

| 假设 | 被否后结论如何变 |
|---|---|
| dn 是**吞吐/并行**受限（慢线程为关键路径） | 若是**延迟受限**，实测收益 < −19.5%，但方向仍成立 |
| 热度文件（246 token）的分布**可代表** 236 token 的实测 | 若差异大，收益按比例缩水 |
| LPT 装桶**不影响** `av` 的缓存局部性 | ⚠️ **本项最大风险**：装桶会打乱"同一专家连续 512 个 rg"的 `av` 复用模式 ⇒ 可能**反噬**（K-DN-006 的收益正来自该复用） |
| 位级 A≡C | 若不成立 ⇒ 立即停并回退 |

> ⚠️ 最后一条必须先说清：LPT 装桶**只重排专家槽位**，但**同一专家的 512 个 rg 仍然相邻**（它们在 `eord` 里是同一槽位）⇒ `av` 复用模式**不变**。这是设计上的关键约束，G2 实现必须保持。

## 10. G3 验证

### 10.1 位级 A≡C（**判据通过**）

> ⚠️ **口径订正（必读）**：首轮 ① 用**默认环境**跑 `VLLM_MOE_2B_VERIFY=1` 得 `nonzero_diffEl=1536`（全部行），**该读数无效且与 BAL 无关**——此时 `VLLM_ACTQ_GU` 已默认开，批式 `Y`（gu 走 int8 近似）与逐 token **精确**参考核本就**非**位级一致。**位级对拍必须在同轨下做**。已改为下述两法：

| 法 | 配置 | 结果 |
|---|---|---|
| **①a 同轨对拍** | `VLLM_ACTQ_GU=0`（批式 gu 回精确轨 ⇒ 与逐 token 参考同轨），`VERIFY=1`，ctx=40 | BAL=0 **1536 行 nonzero=0**；BAL=1 **1536 行 nonzero=0** ⇒ 二者同等于参考 ⇒ **BAL=0 ≡ BAL=1 位级** |
| **①b 默认环境 TOKIDS** | 默认 env（actq_gu 开），ctx=246，n=12 greedy | BAL=0 与 BAL=1 **12/12 逐位一致**：`151667 198 99692 3837 20002 104029 11622 104811 105321 104136 2073 100062` |

⇒ **位级 A≡C 成立**（只改任务映射，浮点表达式与累加序一字未动，与预期一致）⇒ **零质量代价**（无需质量门）。

### 10.3 机理复核：**负载不均完全解释效应**（G0 上界订正）

用 `VLLM_MOE_DN_BAL_VERBOSE=1` 取**逐层**连续切分不均（48 层）：

| 量 | 值 |
|---|---|
| 连续切分 `max/mean` | min **1.072** / **中位 1.318** / max **1.803** |
| LPT 装桶后 `max/mean` | **1.000（全 48 层）** |
| ⇒ 由中位预测 dn 降幅 | `1 − 1/1.318 = **24.1%**` |
| ⇒ 实测 dn 降幅 | **24.99%** |

**⇒ 机理 = m_e 长尾负载不均，吻合在 ~0.9pp 内。**

> **订正（就地，重要）**：§4 预登记上界 **dn −19.5% / prefill −12.6%** 基于 **246-token 热度采样文件**（§3.2 的 `max/mean=7.19` ⇒ 连续不均中位 1.243）。**运行期逐层实测中位为 1.318**（采样低估了偏斜）⇒ 上界**订正为 dn ≈ −24.1% / prefill ≈ −15.4%**。§4 原文保留以留痕。
