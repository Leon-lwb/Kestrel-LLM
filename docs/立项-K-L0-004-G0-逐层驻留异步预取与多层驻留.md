| 项 | 内容 |
|---|---|
| **立项 ID** | **K-L0-004** |
| **标题** | 逐层驻留推理改为**异步加载** + 按内存**一次驻留 ≥1 层**，以消除"加载其它层"的延迟瓶颈 |
| **目标** | 判定「加深/显式化异步预取 + 多层驻留」能否降低逐层驻留的端到端时延 |

## 1. 用户方案（原文拆分）

> 「逐层驻留推理是否可以做成**异步加载**的方式，根据内存情况可以**一次驻留 1 层以上**，来解决因为**加载其他层**的延迟瓶颈」

拆成两个诉求：
- **(a) 异步加载**：计算第 L 层时，异步把第 L+1…层读入（把 `Σ(compute + io)` 变成 `max(compute, io)`）；
- **(b) 多层驻留**：按可用内存一次常驻 ≥1 层，减少重读。

## 3. 步骤 ①：全仓查证 —— **两个诉求都已在引擎里**

| 诉求 | 现状 | 出处 |
|---|---|---|
| **(a) 异步加载** | ✅ **已有**：进入层 L 时 `MADV_WILLNEED(layer+1)`（Linux = **内核异步预读**）+ 选路点按 top-k 专家 `WILLNEED` + 初始 `vqf_prewarm_worker`（独立 pthread 分离线程逐页 touch） | [vqf.c L1363-L1370](../src/model/vqf.c#L1363-L1370)、[L1462](../src/model/vqf.c#L1462)、[L574-L596](../src/model/vqf.c#L574-L596) |
| **(b) 多层驻留** | ✅ **已有**：`VLLM_VQF_STREAM=N` 的 **keep=N** ⇒ 逐出 `layer−keep`，前 N 层常驻；另有专家粒度窗口 `VLLM_EW`/`VLLM_SA` | [vqf.c L1313-L1341](../src/model/vqf.c#L1313-L1341)、[L895-L1093](../src/model/vqf.c#L895-L1093) |

⇒ **用户方案的"机制"不需要新开发**；唯一"缺口"是 **预取窗只有 1 层**（无更深流水线）与 **依赖内核页缓存 readahead**（无显式 I/O 线程 + 完成跟踪）。本 G0 因此只回答一件事：**加深/显式化这套异步，能否有收益？**

## 4. 步骤 ②：决定性实测（零代码，用既有探针）

**装置**：`VLLM_VQF_STREAM=1`（keep=1，最大流转）+ `VLLM_VQF_STREAM_COLD=1`（驱逐连带丢页缓存 ⇒ 真冷档）+ 每轮前 `drop_caches`。
**对照**：`VLLM_STREAM_PROBE=1` 关掉 `WILLNEED(l+1)`（=**关异步预取**）；`=2` 关掉 `DONTNEED(l−1)`（=**不驱逐**）。

| 档 | prefill (32 tok) | decode | rss_after | 凭证 |
|---|---|---|---|---|
| **P0 现状**（DONTNEED + WILLNEED l+1） | **231.166 s** | **115114 ms/tok** | 504,844 kB | `[VQF-STREAM] enabled keep=1 nl=48 segs=11 per-layer=334.1MB` |
| **P1 关异步预取**（`PROBE=1`） | **231.519 s** | 114336 ms/tok | 504,172 kB | `[STREAM-PROBE] mode=1 … expert_segs=3` |
| **P2 不驱逐**（`PROBE=2`） | 229.621 s | **888 ms/tok** | **11,738,456 kB** | `[STREAM-PROBE] mode=2 …` |

### 判读

1. **异步预取的贡献 = +0.2%**（P0 231.166 s vs P1 231.519 s）——**噪声级**。
   ⇒ 现有 `WILLNEED(l+1)` 预取**没有提速**：介质已被打满，预取无法提升吞吐（只能改"谁先读"，不能改"总共读多少/多快"）。
2. **驱逐（而非预取）才是决定性动作**：P2 关掉 `DONTNEED` ⇒ 权重驻留 RAM（RSS 504 MB → 11.7 GB）⇒ decode **115114 → 888 ms/tok = 129.6×**。
3. **反算冷档带宽**（须披露）：专家段 `108 MB × 3 × 48 = 15.55 GB`；`15550 MB ÷ 231.2 s = **67.3 MB/s**` ≈ 板端 SD 顺序带宽峰值（[K-L0-001 §8.4](立项-K-L0-001-G0-每层有效块动态加载权重.md) 实测 62–65 MB/s）⇒ **冷档 prefill 就是"以 SD 峰值把 15.55 GB 读一遍"**，无重叠余地。

---

## 5. 步骤 ③：可达上界（反算，标的 = decode 每层计算窗口）

> 异步的收益上界 = `min(计算时间 × 介质带宽, 需读字节)`；即**只有"每单位计算时间能读到的字节 ≥ 每层需读字节"时，异步才可能全隐藏**。

| 粒度 | 每层需读 | decode 每层计算窗口 | 需要的带宽（才能隐藏） | 板端 SD 67 MB/s 可掩盖 | 缺口 |
|---|---|---|---|---|---|
| **层粒度** | 334.1 MB | ≈ 18.5 ms（888 ms/48 层，P2 实测） | **≥ 18.1 GB/s** | 1.2 MB | **270×** |
| **专家粒度** | 20.25 MB（`108×3×8/128`） | ≈ 18.5 ms | **≥ 1.1 GB/s** | 1.2 MB | **17×** |

⇒ 即便把介质换成 NVMe（~3 GB/s），**专家粒度才勉强接近**，层粒度仍差 6×；板端 SD/eMMC **完全不可能**。

---

## 6. 判定

### 6.1 结论

**不立项。** 三条（均由本次实测支撑）：

1. **诉求 (a) 异步加载**：机制已存在，且**实测贡献 0.2%**——介质带宽饱和 ⇒ 异步只能"重叠"，不能"加速"；加深预取窗/建显式 I/O 线程**改变不了这个上界**。
2. **诉求 (b) 多层驻留**：机制已存在（`keep=N`）。但 **decode 每 token 必须过全部 48 层** ⇒ **部分驻留必然每 token 重读 `(nl−keep)` 层**，把 decode 从 RAM 速度（0.888 s/tok）拉回 **SD 速度（115 s/tok，130× 慢）**。⇒ **唯一有效的是"完全驻留"，不是"驻留 ≥1 层"。**
3. **对当前资产的净影响**：30B-q4 的 RSS（11.7–13.5 GB）**装得下** 15.6 GB RAM ⇒ **不该驱逐**（P2 就是最优档）；一旦驱逐，只有灾难性代价。

> 一句话：**"多层驻留 + 异步"解决的是"读得慢"，但这里的瓶颈是"介质太慢 + 每 token 必须读完所有非驻留层"——异步不能减少字节，驻留才能，而驻留受 RAM 容量钉死。**

### 6.2 成立条件（`feasibility_conclusion_timeliness`，条件补齐即翻正）

逐层驻留 + 异步预取产生**正收益**的条件是下列**至少一条**成立：

| # | 条件 | 与板端现状 |
|---|---|---|
| ① | 介质有效带宽 ≥ **1.1 GB/s**（专家粒度）且 decode 每层计算窗口不缩小 | 板端 SD 67 MB/s / eMMC 313 MB/s ⇒ **差 3.5–16×** |
| ② | decode 每层计算窗口显著变大（**大 batch** / 长上下文 attention 占比高 / prefill 主导） | 当前 decode 18.5 ms/层 ⇒ 需 ≥16× ⇒ 需 batch≈16+ |
| ③ | 模型**仅略微**超出 RAM（deficit 层数 ≲ 0.1 层） | 需 file ≤ RAM + ~1 MB ⇒ 不现实 |

### 6.3 判定敏感项

| 假设 | 若被否，结论如何变 |
|---|---|
| 「SD 顺序带宽 67 MB/s 是地板」 | 若介质换 NVMe（≥1.1 GB/s），**专家粒度分支翻正**（层粒度仍否） |
| 「decode 每 token 必须过全部层」 | 若存在层跳过/早退（如 MoE 层稀疏跳层），可减少冷层数 ⇒ 部分翻正；当前无此机制 |
| 「RAM 15.6 GB」 | 若可加内存到 ≥ file，**整个方向消失**（全驻留最优，本项无对象） |

2. **未测时间局部性**（相邻 token 复用同专家，`VLLM_SA` 走这条路）：与"异步预取/多层驻留"是不同问题，见 [K-L0-003 §8.6](立项-K-L0-003-G0-热度累积与热单元驻留.md)。

## 9. 补测（2026-10-09）：**8B 稠密模型**

> 回应用户"有没有测 8B 稠密"。主实验（§4）载体是 30B-A3B（MoE）；本节补 **8B 稠密** `qwen3vl8b.q4.vqf`（legacy VQF，nl=36，per_layer 103.5 MB，**文件 6.3 GB < 15.6 GB RAM**）。

**口径**：预热后**全热**（页缓存已装下），A(逐层驻留关)/B(`VLLM_VQF_STREAM=1`)/C(`=16`) **交错 2 轮**，ctx=246，n=8，t4，performance。

| 档 | prefill | decode (ms/tok) | rss_after_prefill | MemAvailable |
|---|---|---|---|---|
| **A 关（默认）** | 11.69 / 11.82 s | **189 / 220** | 4105 MB | 15578 → 15579 MB |
| **B keep=1** | 11.86 / 12.01 s | **329 / 338（+74% / +54%）** | **475 MB（−88%）** | 15579 → 15577 MB（**−2 MB**） |
| **C keep=16** | 11.78 / 11.83 s | 269 / 273（+42% / +24%） | 2031 MB | ~0 |

**判读**：

1. **内存是假收益**：RSS 4105 → 475 MB（**−88%**），但 **MemAvailable 基本不变（−2 MB，噪声级）** ⇒ 干净 file-backed 页仍留在页缓存，**RSS 只是"搬家"**（**实证 K-L0-001 §3.2 的判读**）。
2. **代价是真实的**：decode **+54~74%（keep=1）/ +24~42%（keep=16）**——驱逐越多、重缺页越多、越慢。
3. **prefill 基本不变**（+1~2%）：prefill 本就需全量权重，驱逐不改变总读量。

⇒ **8B 稠密：逐层驻留 = 纯负收益**（内存零收益 + decode 慢 24–74%）⇒ **不该开 `VLLM_VQF_STREAM`**。
与 30B（文件 > RAM：驱逐代价 **130×**、异步救不了）互补 —— **两类资产都不支持逐层驻留**：8B 是"**没有收益**"，30B 是"**有代价且异步无效**"。

**对 §6 判定的影响**：不翻转（维持"否"），且**加强了** §6.2 成立条件 ③（"模型仅略超 RAM"）：连"文件 < RAM"的 8B 都被证明无收益，③ 的实际窗口比原先估计的更窄。
