## 2. 对象与现状（读代码 + 仓内既有实测）

### 2.1 已有实现（**不是从零开始**）

`--spec` = n-gram 自推测 + `st_qwen_model_prefill_batch` **一次并行验证**（权重只读一次）+ 贪婪接受 + KV 回滚。默认 **关**（`g_spec=0`，[main.c#L638](../src/main.c#L638)），`--spec-k` 默认 4（上限 16）。

| 项 | 现状 |
|---|---|
| 草稿源 ① | n-gram：`spec_build_draft()` 窗口 8→3，**每轮线性扫全历史**（[vllm_server.c#L1026-L1048](../src/serve/vllm_server.c#L1026-L1048)） |
| 草稿源 ② | `VLLM_SPEC_DRAFT=<文件>`：**自研 1 层草稿头**（q/k/v/o + gate/up/down，legacy q8，[vllm_safetensors.c#L9010-L9035](../src/model/vllm_safetensors.c#L9010-L9035)）——**就是 MTP 的等价物** |
| 生效性凭证 | `[SPEC] tries=%d hits=%d kv_rolls=%d (%.0f%% draft hit)`（[#L1466-L1471](../src/serve/vllm_server.c#L1466-L1471)）**已有** |
| 启用约束 | 仅贪婪文本（`temp<=0 && top_p>=1 && min_p<=0`）、`!g_l3_evict`、`!g_sparse_attn`、`batch_max<2` |

### 2.2 三条验证路径（**语义与代价完全不同，必须分开**）

| 路径 | 触发 | 语义 | 代价 |
|---|---|---|---|
| **默认：回滚 + 重放** | 无 env | KV 位级一致 | 批验证 **+ 已接受前缀逐 token 重放**（[#L1310-L1321](../src/serve/vllm_server.c#L1310-L1321)）⇒ **结构上 ≥ 无 spec** |
| **VEXACT** | `VLLM_SPEC_VEXACT=1` + `VLLM_SPEC_VNORM=1`，`k≤8` | 声明批验证 KV 与 decode **位级等价**（2026-09-24 板端 **8B-q4** L1 对拍 PASS，[#L1050-L1064](../src/serve/vllm_server.c#L1050-L1064)） | 免重放 |
| **FAST** | `VLLM_SPEC_FAST=1` | 免重放 + asm 快路；**非位级**（near-tie 可翻转，实测 `repeat_same 90 vs 86`，[#L1066-L1077](../src/serve/vllm_server.c#L1066-L1077)） | 免重放，但**须按容差登记** |

## 3. 三个测量（**本 G0 的执行内容**）

### M1 · verify 经济学（定天花板）

- **测什么**：板端 `cost_verify(K)`（K=2..8）与 `cost_decode(1)`，得 **U(K) = cost_verify(K) / cost_decode(1)**（即"K 个 token 的专家并集"倍数，与 Strata 同定义）。
- **怎么测**（零代码）：`--stream-test` 固定 prompt；用 `VLLM_MOE_2B_SEG=1` 的 `[2BSEG-ARM]` gu/dn 段 + `[PREFILL-TIMING]`，比较 `st_qwen_model_prefill_batch(nb=K)` 与 K 次单 token forward 的段耗时。
  > **✅ 就地订正（M1 执行期，§8.1）**：原写法「用 `--stream-ctx K` 取 K=2..8」**不可执行**——`--stream-test` 的 prompt 模板最少 ~32 token，取不到小 K。**实际改用 `--prefill-batch K`**（把 pn=230 的 prefill 切成 K-token 小批，每批打一行 `[2BSEG-ARM]`）⇒ 任意 K 均可测，且**零代码**成立。
- **对照**：Strata U(2)=**1.75**、U(3)=**2.4**、U(4)=**3.05**。
- **先写死的判据**：**若 U(4) ≥ 3.6**（⇒ 4 个 token 只值 `4/3.6 = 1.11×`）⇒ **投机天花板 < 1.11× ⇒ 直接否**（除非接受率≈100%）。

### M2 · 接受率分 workload（定适用面）

- **测什么**：三类真实 prompt 各 ≥10 题——**math（数字递变）/ code（模板与重复）/ 多轮对话（复述）**，记录 `[SPEC] … (% draft hit)` 与 tpot。
- **口径**：`--spec` on/off **同轮交错 ≥3 轮**，t4、governor=performance、逐轮记 `mmcblk1` 读量并按**零缺页**筛选。
- **先写死的判据**：**三类全部入表**（`nonmonotonic_benefit_no_cherry_pick`）；预期 math ≈ 0%（wiki 已实测同类 0%）。若数学与代码都低 ⇒ 唯一价值退化为"模板/复述"档。

### M3 · 三条路径的代价差（定形态）

- **待证伪的假设（读代码推得）**：默认「回滚+重放」= **批验证 + K 次 decode 重放** ⇒ **结构上必然慢于无 spec**——这很可能是 x86「反慢 2.4×」的主因（而非"投机本身无效"）。
- **测什么**：同 prompt，`无 spec` / `默认` / `VEXACT` / `FAST` 四档交错，比 tpot。
- **先写死的判据**：若默认档确认 >1.0×（更慢）⇒ **默认路径必须改**（或显式拒绝），否则 `--spec` 只在 VEXACT/FAST 下有意义。
- **⚠️ 前置**：VEXACT 的位级前提在 **8B-q4 dense** 上验证；**30B-A3B MoE 批式路径（K-DN-006 改过 dn 任务序）未复验** ⇒ 若要在 MoE 上用 VEXACT，**必须先重跑 L1 位级对拍**（`VLLM_SPECL1`，[vllm_safetensors.c#L16579-L16595](../src/model/vllm_safetensors.c#L16579-L16595)）。

## 4. 可达上界（**反算，须披露推导式**）

单轮经济性（与 Strata 同式）：

```
接受 a 个草稿 ⇒ 本轮产出 (a + 1) 个 token（+1 是 bonus）
本轮成本 = U(K) × cost_decode(1)
⇒ 加速比 = (a + 1) / U(K)
```

代入 Strata 的 U(K)（**外借对照值，非本站实测**）：

| K | U(K) | 乐观（a=K，全接受） | 现实（按我们 75% 命中） |
|---|---|---|---|
| 4 | 3.05 | (4+1)/3.05 = **1.64×** | (3+1)/3.05 = **1.31×** |
| 8 | 5.2 | 9/5.2 = **1.73×** | (6+1)/5.2 = **1.35×** |

⇒ **上界预登记：decode 轴 ≈ 1.3–1.7×**（与仓内已实测的 1.30× **自洽**）。

**口径（关键）**：这是 **decode 轴**的倍数。**prefill 不受影响**（本轮主线是 prefill GATEUP 96%，**与本项正交**）⇒ 本项**不改变**上一轮的性能结论，只决定"decode 交互延迟"这一轴。

## 5. 判定与敏感项（G0）

**立项（可达性成立）**：三个测量全为零/低代码风险；且 M3 已由读代码给出可证伪的具体假设。

| 敏感项 | 被否后结论如何变 |
|---|---|
| U(K) 在 **纯 CPU MoE** 上与 Strata（GPU + CPU-expert 混合）同量级 | 若 CPU 上专家只能全从 DRAM 取（无 VRAM 命中缓存）⇒ 并集增长更快 ⇒ 天花板更低 ⇒ 可能直接否 |
| VEXACT 的位级前提在 **30B-A3B 批式路径**仍成立 | 若否 ⇒ 只剩默认（结构性负）或 FAST（**非位级**，须重冻判据） |
| 三类 workload 中至少一类（预期 code）接受率足够 | 若 math/code 均低 ⇒ 唯一用途退化为"多轮/模板"档 |
| 投机与 SC 多分支正交可叠加 | 若 `batch_max<2` 等约束与在线 SC 路径冲突 ⇒ 只能离线/单路用 |

### 8.1 口径订正（先披露）

| 取 K 的手段 | `--stream-ctx K`（K=2..8） | **不可执行**：`--stream-test` 的 prompt 模板最少 **~32 token** ⇒ 取不到小 K |
| 改用 | — | **`--prefill-batch K`**：把 pn=230 的 prefill 切 K-token 小批，每批打印一行 `[2BSEG-ARM]`（**零代码**） |
| 门槛 nb≥2 | — | `st_moe_ffn_sparse_q4_batch_arm` 有 `nb < 2 ⇒ return 0`（[#L15163](../src/model/vllm_safetensors.c#L15163)）⇒ **K=1 无批式数据**，回退逐 token（实测证实：`lines=0`） |

口径：板端 30B-A3B，`--stream-test --stream-ctx 240`（**pn=230**），t4，governor=**performance**，`VLLM_MOE_2B_SEG=1`。⚠️ K=1/K=2/K=6 轮有页缺页（sd=6848/312/48 sectors），已披露。

### 8.2 实测：批式 MoE 每 token 代价的 K 曲线

`[2BSEG-ARM]` 48 层合计（全部小批求和）。每 token 代价 = `[STREAM] prefill` 总时 ÷ 230。

| K | 小批数 | MoE 合计 ms | gu | dn | 批式**每 token** ms | **U(K)=C_batch(K)/C_dec** | 上限 =326/每token |
|---|---|---|---|---|---|---|---|
| **1**（回退逐 token，无 `[2BSEG]`） | — | — | — | — | **337.2**（=参考） | — | — |
| **2** | 115 | 93294.1 | 46507.9 | 44756.7 | **434.5** | **2.67** | **0.75×** |
| 3 | 77 | 80455.9 | 41116.7 | 37548.3 | 371.4 | 3.42 | 0.88× |
| **4** | 58 | 77152.1 | 40370.4 | 35629.9 | **355.9** | **4.37** | **0.92×** |
| 6 | 39 | 68399.8 | 36511.0 | 30470.4 | 318.3 | 5.86 | 1.02× |
| **8** | 29 | 63281.8 | 34146.3 | 27942.1 | **289.6** | **7.11** | **1.13×** |
| 16 | 15 | 52341.2 | 28619.3 | 22598.7 | 236.1 | 11.59 | 1.38× |
| 32 | 8 | 43400.4 | 23407.3 | 18942.1 | 197.1 | 19.35 | 1.65× |
| **256**（单批） | 1 | 39032.6 | 21967.3 | 15954.1 | **177.9** | 139.7 | **1.83×** |

**decode 单 token 参考**（`--stream-ctx 0 --stream-n 10`，ctx≈32）：**326 ms/tok**（10 步 325–327，极稳）。
**长上下文 decode 参考**（不切块跑完 pn=230 后 decode 4 步）：420/419/421/333 ms ⇒ **≈400 ms/tok**。

**对照 Strata**：U(2)=**2.67 vs 1.75**、U(4)=**4.37 vs 3.05** ⇒ **我们的 CPU-MoE 比 Strata 的 GPU+CPU-expert 混合更难批（1.4–1.5×）**。

### 8.3 判定：**默认档（K=4）否 —— 命中预登记规则**

1. **规则命中**：**U(4) = 4.37 ≥ 3.6** ⇒ 按 §3 先写死的判据 **「直接否」**。
2. **直读更硬**：K=4 时批式每 token **355.9 ms > decode 326 ms** ⇒ 上限 **0.92×**，即**即便 100% 接受也慢 8%**；K=2 更差（**0.75×**）。⇒ 与仓内「**x86 反慢 2.4×**」同一方向、同一机理。
3. **U(3)=3.42 < 3.6 但方向仍负**（0.88×）⇒ 不是"卡在门线上"，而是 **K≤4 全区间净负**。
4. **取舍**：`--spec` 只需 K=0（关）或 K=4（默认档）两种现实用法；**K=4 已判否** ⇒ **本项按预登记规则收口：不立项**。

### 8.4 顺带产出的三条引擎事实（**与投机无关，但有独立价值**）

| # | 事实 | 意义 |
|---|---|---|
| ① | ~~**批式 MoE 有 ≈15 ms/层/次调用 的固定代价**（两参数仿射拟合 `MoE_chunk ≈ 732 + 149.6·K`）~~ → **⚠️ 就地订正（同轮，三参数分解后）**：真因是**专家并集未饱和**，不是"固定开销"。用并集模型 `MoE_chunk(K) = W·D(K) + C·K + F`（`D(K)=128(1−0.9375^K)` 为 top-8/128 的期望去重专家数）按 K=2/8/16 拟合：**W ≈ 32.7 ms 每去重专家·每 chunk(=0.68 ms/专家/层)**、`C ≈ 30.1 ms/token·chunk`、**`F ≈ 244 ms/chunk（仅 5.1 ms/层）`**。⇒ **固定项其实很小**；K=4 时 MoE 的 **72% 是"去重专家数"项** | **真正的机理**：K=4 时去重专家 ≈ **29/4 = 7.25 个/token**，而 decode 单 token 就是 **8 个** ⇒ **小 K 下批处理不减少任何专家权重流量**；只有 **K≳16 并集饱和（K=16→5.3、K=32→3.5、K=256→0.5 个/token）** 才真正摊薄 ⇒ **这是结构性结论，不是可优化的开销**（原文"可另立候选"**撤回**） |
| ② | **prefill 每 token 177.9 ms（K=256，饱和）vs decode 326 ms（ctx32）/≈400 ms（ctx230）** ⇒ **decode 比饱和批处理慢 1.8–2.3×/token** | 这是投机解码的**理论上限**（全接受时）；也说明**decode 是"批不起来的低效点"** |
| ③ | `--prefill-batch 1` 的**逐 token 回退**代价 337.2 ms/token ≈ decode 326 ms | 两条 per-token 路径代价一致 ⇒ 上面 U(K) 的分子分母**同源可比** |

### 8.5 未覆盖区间（**不得用同一判据放行**）

预登记判据只写了 **U(4)**（默认 `--spec-k 4`）。实测显示 **K≥8 起上限转正**：

| K | 上限 | 打平所需接受率（`(acc+1)/K > 1/上限`） |
|---|---|---|
| 8 | 1.13× | acc > 6.08/8 = **76%** |
| 16 | 1.38× | acc > 10.6/16 = **66%** |
| 32 | 1.65× | acc > 18.4/32 = **58%** |

⇒ 存在一个**理论可盈利档**（大 K + 高接受率 + 长上下文，典型是**代码/模板/复述类文本**）。但：
- 该区间**不在原冻结判据内**（判据只覆盖 K=4）⇒ 若要推进**必须重新预登记**（含 M2 的三类接受率实测），**不得用本次结果放行**；
- 且 `VEXACT` 路径的 `K≤8` 上限、以及 30B MoE 批式路径的位级前提**均未复验**。

### 8.6 M1 判定小结

> **M1 = 否（默认档 K=4 净负，U(4)=4.37 ≥ 3.6）** ⇒ **K-SPEC-011 按预登记规则收口：不立项**（`--spec` 维持默认关）。
> **登记未覆盖区间**：K≥8 有正上限（1.13–1.83×），但需高接受率且**须重新预登记**方可推进。

## 9. 全项收口裁定（2026-10-08，用户裁定）

**K-SPEC-011 全项关闭，K≥8 档不推进。** 三条依据（§8 已测）：

1. **盈利机制唯一 = 专家并集饱和**（§8.4① 订正后）：K≤8 时去重专家/token 仍 **6.5–7.25**（decode 为 8）⇒ **不省任何专家权重流量**；真正摊薄需 **K≥16–32**。
2. **打平阈值与主力 workload 不相容**：K=8/16/32 需 acc **>76%/66%/58%**，而在线的 **math 档 n-gram 实测 0% 命中**（数字递变）；仅 code/模板/复述档可能达标。
3. **天花板低 + 成本高**：全局上限 **1.83×**（decode 轴，需 K=256 不可达）；而投入含重冻判据 + M2 三类实测 + G2（大 K + 自适应决策器 + 索引化草稿器）+ **30B MoE 批式路径的位级复验**（`VEXACT` 原验证只在 8B dense）。

**留仓**：`--spec`（默认关）、`[SPEC] tries/hits` 凭证、`tools` 侧 M1 测量法（`--prefill-batch K` 切块）—— 后续若要重开，M1 口径可直接复用。
**未做**：M2（三类接受率）、M3（三路径代价差）—— 随本项关闭不再执行。
