## 1. 原理：句子向量嵌入是什么

与生成式 LLM 不同，**嵌入模型不产 token，只产一个向量**：

```
文本 → [编码器前向] → 取某个位置的隐藏状态 → 池化 → L2 归一化 → 向量 (dim=1024)
```

本模型（`Qwen/Qwen3-Embedding-0.6B`）的口径由它的配置钉死：

- **last-token pooling**（`1_Pooling/config.json: pooling_mode_lasttoken=true`）：取**最后一个 token** 的隐藏状态。
- **L2 归一化**（`modules.json` 的 `2_Normalize`）：输出单位向量 ⇒ 余弦相似度 = 内积。
- **配方关键**：`tokenizer_config.json` 的 post_processor 是 `TemplateProcessing(single=[Seq, <|endoftext|>])` ⇒ **编码恒在尾部追加 EOS=151643**。所以 last-token 取到的正是 **EOS 位置**。漏掉这一步，末位就落在最后一个实词上，向量与官方不一致。

**几何事实**：`Qwen3-Embedding-0.6B` 的 `config.json` 是 `Qwen3ForCausalLM`，文本骨干与 **Qwen3-0.6B 100% 同构**（dim 1024 / 28 层 / 16 heads / 8 kv_heads / head_dim 128 / ffn 3072），差异只有两点：

| 差异 | 说明 |
|---|---|
| `vocab_size=151669` | 比 0.6B base（151936）小 |
| **无 `lm_head`** | tied embeddings ⇒ 加载时 `lm_head` 缺失回退到 `memcpy(token_embed)` |

⇒ 引擎**已有**的 Qwen3 前向不用改，只需要：① 加载器认这个模型目录；② 加一个「取值钩子」把末位隐藏状态拷出来做 L2。

## 2. 真正的难点：引擎的分词器不是 BPE

这是本项最有教学价值的部分。

### 2.1 症状

同一句话喂 HF `tokenizers` 与引擎，**id 序列不一致**：

```
"A train travels at 60 miles per hour for 2.5 hours. How many miles does it travel?"
  native (HF tokenizers) : 24 tokens
  engine (修复前)        : 22 tokens   ← 仅前 4 个 token 一致
```

端到端后果：向量在 `Instruct:/Query:` 这类文本上余弦低至 **0.83**（正常应 >0.99）。

### 2.2 根因（读源码得到，不是猜）

引擎 `vllm_tokenizer_qwen.c` 的编码器是：

- **UTF-8 最长前缀贪心**：`find_longest_match_qwen` 线性扫描全词表取最长匹配；
- **从未实现 BPE 合并序**（`Explain` → 贪心 `Expla`+`in`，HF 为 `Ex`+`plain`）；
- 且 `qwen_tokenizer_encode` 内联把空格吞掉再试 `Ġ` 前缀 ⇒ 数字/标点前的**独立空格 token(220) 会丢失**，后续 id 整体偏移。

排除了两个「看起来像」的原因：
- **不是 vocab.bin 的问题**：换用 Qwen2.5 原生 `tokenizer.json` 重建 vocab 后 **ids 完全不变** ⇒ 引擎的 BPE 分割**不由 vocab.bin 驱动**（vocab.bin 只存 token 字节串，不含 merges）。
- **不是模型问题**：Qwen3 与 Qwen2.5 主区 `0..151642` 的字节级 piece 本就同源。

⇒ 结论：必须**在引擎里实现真 byte-level BPE**。

### 2.3 原理：byte-level BPE

标准 GPT-2 家族 BPE 分三步：

1. **预分词**（正则切 piece）：Qwen 用 GPT-2 家族正则，把空格并进词首（`Ġ`）、数字单列、标点/CJK 分组等。
2. **词内按 merge rank 合并**：反复把 rank 最小的相邻符号对合并成一个符号（rank 来自 `tokenizer.json` 的 `model.merges`）。
3. **查词表出 id**。

### 2.4 关键坑：引擎词表域 ≠ 标准 GPT-2 repr 域

标准 GPT-2 的 repr 域把**所有**字节经 `bytes_to_unicode` 映射（`≥0x80` 也映射）。实测发现引擎 `vocab.bin` 是：

> **原始字节**，**仅把 `<=0x20` 的字节**做 `bytes_to_unicode` 编码（空格→`Ġ`=C4 A0、`\n`→`Ċ`=C4 8A）；**CJK 等 ≥0x80 字节原样**。

实测该变换与 `vocab.bin` **151643/151643 逐字节一致**。所以生成 merges 时必须把标准 repr **转到引擎域**再落盘。

## 3. 工程实现

### 3.1 转换器：修复 Q4-4x4 全局门

转换器 `vqf_convert` 原逻辑是「任一矩阵几何不满足 `vc/q_out/k_out/dim/ff` 就**全局**关闭 Q4 repack」。本模型 `vocab_size=151669`（**奇数**）触发了这个门 ⇒ 写出缺 `VQF_FLAG_Q4_4X4` 的文件 ⇒ 被引擎 `vqf_load` 的 layout 校验拒绝（`file=0x21 engine=0x3`）。

**修法**：改为与引擎一致——**不做全局门**，逐矩阵 repack 自带 `rows%4 / cols%32` 门控。修正后 `flags=0x23`。

```bash
vqf_conv --model <hf_dir> --convert-vqf <out>/model.vqf --wmode dual   # Q8+Q4, flags=0x23
```

### 3.2 取值钩子（引擎侧最小改动）

- `vllm_safetensors.c` 加 `g_embed_out` / `g_embed_dim` + `st_embed_request(float *out, int dim)`。
- 在 prefill 收尾（末尾 final-norm 之后、LM head 之前/之后）把 `normed_b` 做 **L2 归一化**后拷出，并**一次性清空钩子**。
- **未登记时对生成路径零行为改变**（这是关键：同一个 prefill 内核既服务 chat 也服务 embedding）。

### 3.3 生成 merges.bin（一次性）

```bash
python tools/gen_merges_bin.py <hf_dir>/tokenizer.json <out>/merges.bin
```

二进制 `QBM1` 格式：`u32 头 + n_merges×(u16 llen,rlen,bytes) + n_added×(u32 id,u16 len,bytes)`。merges 按 **(llen, rlen, left, right)** 排序存 rank，C 侧二分查找。

**为什么用二进制而不是 JSON**：文件里内嵌 `\` 等转义/计数不可靠，JSON 解析坑多；预生成二进制一次到位。

### 3.4 C 侧编码器

- `tok_bpe_load_bin`：载入 `merges.bin`（开放寻址哈希 `(left,right) → rank`）。
- `tok_bpe_encode`：
  1. **added_tokens 整串最长匹配**（`<|im_*|>` 等 26 个）→ 直接出 id；
  2. **Qwen 预分词正则近似**（g1 收缩 / g2 可选前缀+字母 / g3 单数字 / g4 其它段 / g5-7 空白换行）；
  3. raw 字节 → **引擎词表域**；
  4. **按 merge rank 最小合并**（左优先）；
  5. 逐符号查词表出 id；
  6. **added 硬边界**：piece 不得跨过后面出现的特殊 token 起始——否则 `。`+`<|im_end|>` 会被 g4 并成一段、模板尾错位。
- **`merges.bin` 缺失 → 回退旧贪心**（`VLLM_TOK_LEGACY=1` 可强制旧路径做位级回归对照）。

### 3.5 CLI / HTTP

```bash
./vllm_kestrel --model <dir> --embed "hello world"          # 裸文本，不套 chat 模板
echo -n "任意中文/多行" | ./vllm_kestrel --model <dir> --embed-stdin   # UTF-8 安全（规避 Windows argv ANSI 损坏）
./vllm_kestrel --serve --auto-load --model <dir> --model-id qwen3-embedding-0.6b --port 8098
curl .../v1/embeddings -d '{"input":["What is 12*8?","Gravity is a force."]}'
```

⚠️ 部署务必显式 `--model-id`（否则响应 `model` 会回落到 serve 硬编码默认）。

## 4. 实测结果（质量门）

### 4.1 分词位级门 20/20

`tools/tok_gate.py`（x64）与 `board_tokcheck.py`（板端）跑同一批 golden，**20/20 PASS**。覆盖：golden 句、`Instruct:/Query:` 指令串、收缩词、中文（含全角标点）、ChatML 模板全串、代码缩进、URL/邮箱、数字/小数/负数、多空格/换行。

> 修复前（贪心）同批仅 **12/20**。

### 4.2 端到端保真（vs HF `AutoModel` + last-token + L2）

| 文本 | BPE 前余弦 | **BPE 后余弦** |
|---|---|---|
| `hello world` | 0.9973 | **0.9973** |
| `Explain gravity` | 0.979 | **0.9965** |
| `Query:Explain gravity` | 0.904 | **0.9967** |
| 完整 `Instruct: …\nQuery:…` | 0.832 | **0.9947** |

⇒ BPE 后 E2E 余弦 **0.994–0.997**，残余 0.3–0.5% 是 **Q8 权重 × int8 激活**的量化误差，非分词/几何问题。

### 4.3 oracle 自证 + 语义可用性

- **官方分数复现**：用官方 Transformers 代码复现 model card 公布值 `[[0.76456,0.14143],[0.13550,0.59995]]` **逐位吻合**；引擎板端 `[[0.7598,0.1648],[0.1427,0.6317]]`，同量级（差 ≤~0.03）。
- **检索排序 sanity**（query 加 `Instruct: …\nQuery:…` 前缀，4 篇候选）：**3/3 把正确文档排第一且裕度清晰**（0.760 vs 0.356 / 0.583 vs 0.195 / 0.694 vs 0.394）⇒ 引擎可作**真正可用的检索嵌入器**，非仅数值对齐。

## 5. 本篇要点回收

| 教学点 | 内容 |
|---|---|
| 嵌入 ≠ 生成 | 不产 token；last-token pooling + L2；**必须确认尾部 EOS 配方** |
| 引擎分词器可能是「伪 BPE」 | 贪心最长前缀 ≠ BPE 合并序；**只有与 HF golden 逐 id 对拍才能发现** |
| 词表域陷阱 | 引擎 vocab 是「原始字节 + 仅 ≤0x20 做 bytes_to_unicode」，与标准 GPT-2 repr 不同 |
| 最小侵入接入 | 用一个**一次性取值钩子**复用既有 prefill 内核，未登记时对 chat 零影响 |
| 位级分词门 | 20/20 覆盖中含 ChatML 模板全串——模板尾错位是最容易被忽视的坑 |

**残余限制（诚实披露）**：NFC 归一化未实现；`\p{L}/\p{N}` 为工程近似；纯 `--wmode q8`（flags=0x21）在 x64 `vqf_load` 后有 AV（未定位），交付用 `dual`；`merges.bin` 是**每模型目录一份**的可选件——**切勿放到可执行文件同目录**（引擎有 exe-dir 回退，会让所有模型切到 BPE）。
