适配篇留下性能坑：CPU 基线 **1.82–2.36 s/图**。本篇走两条路线——先「**把卷积搬到 NPU**」（im2col→GEMM），再「**把 CPU 卷积做快**」（int8 dotprod），最终 CPU 路径**反超**自家 NPU 路径。全程包含两次「数量级路线被数据证否」。

## 0. 先定性能目标与口径

**J5（先冻结）**：CPU 基线中位 **1.82–2.36 s/图**；目标 = NPU/优化后 **≤ 基线的 1/3（≥3×）**，且 J2 不退化。

**口径**：板端 RK3588，serve 常驻，`t4@A76`；⚠️ **NPU 计时必须先固定 `devfreq=performance`**，否则读数严重偏低（漏这一步会得出完全错误的结论）。最终对照官方 RKNN（`rknn_run`，同模型同尺寸）为**信息性**，不进交付链。

## 1. 路线 A：卷积上 NPU（im2col→GEMM）

### 1.1 原理：卷积↔GEMM 的「转置取向」（关键设计）

DIRECT 驱动的 CNA 几何**只标定过小 M × 大 K × 大 N**（`CNA_DATA_SIZE0` 11-bit、`CONV_CON2` 10-bit）。如果把 im2col 的 **M=空间位置**（数千）当 GEMM 的 M，会**溢出 M 编码 / 撑爆 CBUF**（首版即此错，J1 `maxrel` 达 1e9）。

**解法：把卷积转置**——

```
out[oc][p] = Σ_k Wconv[oc][k] · im2col[p][k]
   M = OC (16..512, %4)      ← 小 M，编码放得下
   N = P = OH·OW             ← driver 原生支持大 N 分块
   K = C·KH·KW (补 Kp=32)    ← 大 K
```

于是：「特征 A」= 卷积权重 `nw[cid]=[OC][Kp]`（per-channel scale 复制到各 K 块，语义与 CPU `yconv_q8` 等价）；「权重 W」= im2col `[P][Kp]`（逐像素对称 int8 scale）；**out 布局 = 引擎槽位 `[oc][OH][OW]`，无需转置**。`wkey=0`（im2col 每调用变化，禁权重缓存）。

> **教学点**：**「转置」是为了迁就硬件的编码约束**，不是为了数学。同一份卷积-as-GEMM，正着摆溢出、转着摆就对——这类适配只有读驱动契约才能发现。

### 1.2 显式回退（J4）

`yconv_npu()` 不适用/失败 **显式回退 CPU**：`[NPU] fallback conv ...` + 计数。诊断门：`VLLM_YOLO_NPU_CHECK=1`（逐卷积 NPU vs CPU 对拍）。

**J1（逐卷积）**：`maxabs` **0.02–0.9**（SiLU 后量级）；`maxrel` 大是因为 SiLU 后近零分母，**以 maxabs 为准**。43–63 个卷积全部上 NPU。

### 1.3 里程碑与实测

| 里程碑 | 内容 | 结果 |
|---|---|---|
| **M2** | im2col→GEMM 上 NPU + 最小提交调度 + im2col 单遍化 + C2PSA 卷积下推 | 功能达成 |
| **M3 Phase-1** | **DIRECT 原生卷积**打通 | **`max|Δ| = 0`**（位级） |
| **M3 Phase-2** | 大形状输出几何稳定化 | **证否**（大 OH/OW → DPU 超时/乱码，run-to-run 非确定）⇒ **保守关闭** |
| **J5** | 三版加速 | v8 **6.16–7.37×**、v5 5.74–6.63×、v11 5.04–6.49×（均 ≥3×）✅ |

**J2/J3 全过**：golden v8 66/68、v11 67/71；板端 CPU vs NPU **242/247 配对**，score 差 ≤0.061、框差 ≤9.8px，仅 conf 边缘 ±1；三版 × 9 真图。

### 1.4 原生卷积标定的三轮上界（`feasibility_conclusion_timeliness`）

「追官方」的原生卷积寄存器标定设了**尝试上界**，三轮用尽后**按纪律回退 M2**：

| 轮 | 做法 | 结果 |
|---|---|---|
| 1 | 从官方 `.rknn` 内嵌 **regcmd** 反解字段（`reg@0 \| val@2 \| op@6`，解出 364 个 CNA 块）并逐个采用官方值 | 16×16 **仍全 FAIL** |
| 2–3 | oracle 语料拟合 + 官方 DPU profile 组合 / 带状分块+ARGB 打包 | 确认**结构性差异**（官方自有特征布局）⇒ 不可 1:1 移植；且 DPU profile 反使 8×8 由 PASS 变 FAIL |

⇒ **唯一权威 = 官方 librknnrt 本身**；本引擎「单发 NC1HWC2」布局与官方不同 ⇒ 回退 M2（已过 J1–J5），追官方登记为「待 RK3588 原生卷积寄存器语义突破」。

### 1.5 第二轮攻坚：把 M2 的提交/回读开销压下去（第 5–9 轮）

用 `VLLM_NPU_TIMING` 把 `npu_call` 拆开，得到**最重要的一次重定性**：

```
npu_call 225.6 ms = t_sub(NPU 真执行) 35.8 + hide 90.0 + t_acc(CPU 回读累加) 44.9
                  + t_pack 27.5 + setup 26.1 + …
端到端 ≈ im2col(CPU) 138 + npu_call 256 ≈ 391 ms
⇒ 本引擎 NPU 实际只花 ~36 ms（vs 官方 16.05 ms，仅 2.2×），
   端到端 ~91% 是 CPU 路径！
```

**结论翻转**：差距不是「NPU 内核慢」，而是「**这条路径把工作留在 CPU**」（官方 conv 直接产 requant 结果，无 im2col / 无 CPU 回读累加）。

据此逐项削减 CPU 侧开销：

| 轮 | 改动 | 实测 |
|---|---|---|
| 7 | 权重 staging 跳过冗余 / 并行化打包；im2col 量化去 `lrintf` 改 magic 技巧（位级一致）+ `omp simd` | im2col 138→78 ms、wstg 83→36 ms；serve 1.27× |
| 7+ | scratch 常驻（避免每调用 mmap/munmap）；BO cacheable 实验 | 聚合 −10 ms；cacheable **证否** |
| **8** | **per-call GEMM BO 复用**（移动语义 acquire/release，缓存永不悬空） | `setup` 23.6→4.9 ms；serve cats **509.8→451.7 ms（−11.4%）**；**md5 6/6 全等** |
| 9 | 消冗余 `memset(out)` | **证否**（memset 是顺序写预热，删除把代价转移给累加首读，净 ~1.9 ms 噪声内）⇒ 回退 |
| 5 | 削减提交数（多核/最小提交） | **证否**（多核零收益、单核反而略快；Nt 提上限会 wedge）⇒ npu_call 不由提交数主导 |

## 2. 路线 B：把 CPU 卷积做快（K-YOLO-002，最终赢家）

### 2.1 Phase 0 — 分解 + 可行性先冻

CPU 分解：**conv 占 forward 98.6%**（q8 2371/2405 ms；F32 2189/2223 ms）。dotprod 微基准：**单核 25.5 GOPS vs 标量 1.51 GOPS（16.9×）**。

**先冻结论**：4 核 dotprod 理论下限 ~43 ms、现实 85–170 ms ⇒ **CPU 追平官方 16 ms 不可达**；目标收敛为 **conv ≤200 ms、e2e 150–250 ms**。

### 2.2 Phase 1 — `vdotq_s32` dotprod 卷积（主杠杆）

抽出共享助手 `yolo_im2col_q8()`（NPU 与 CPU 共用，单一真源），新增 `yconv_cpu_dotprod()`：`vdotq_s32` int8×int8→int32 GEMM，反量化 `cs[oc]·rowsc[p]`。

**实测**：conv **2368 → 140 ms（16.9×）**；e2e v8 2455/2300 → **215/200 ms（11.4×）**；J-CPU-2 检测等价全落 K-YOLO-001 J2 容差内；**NPU 路径 md5 6/6 不变**。

> **教学点**：「伪 int8 → 真 int8」的差别就在这里：适配篇里 CPU int8（无 dotprod）**慢 8–11%**；接上 `vdotq_s32` 后 **快 16.9×**。

### 2.3 逐级微调与三次证否

| 级 | 内容 | 结果 |
|---|---|---|
| **1.1** P-分块（钉 L1 跨 oc 复用 imc） | imc 重读已被 A76 L2 吸收 | **证否**（+3.5%）⇒ 回退 |
| **1.2** **4-way ILP**（同 oc 4 位置 × 4 累加链，共用权重向量） | 掩盖 `vdotq` + `vaddvq` 水平归约延迟 | ✅ 139.9→**125.5 ms**（e2e 12.2×） |
| **1.3** 8-way ILP | A76 **寄存器压力 > ILP 收益** | **证否**（+3.7%）⇒ 回退至 4-way |
| **2 勘察** | im2col 显式 NEON 量化 / 裸 `vcvtq_s32_f32` | 前者慢 2%（GCC `omp simd` 更好）；后者**数值破坏**（ARM FCVTZS 是**截断**，非 round-to-nearest）⇒ 回退 |

### 2.4 Phase 2 — 非 conv 并行化（逐位等价）

**关键发现**：YOLO 的逐元素/后处理算子**几乎全单线程**。逐项加 OMP（全部**位级一致**）：

| 算子 | 前 → 后 |
|---|---|
| MAXPOOL / UPSAMPLE / ADD·MUL·SIGMOID | 5.4→1.4 / 3.5→1.0 / 0.6→0.3 ms |
| SLICE / CONCAT | 2.1→1.2 / 6.1→3.6 ms |
| **letterbox**（映射预计算 + c 提外层 + OMP） | **10.9 → 3.0 ms** |
| **DETECT（DFL softmax+sigmoid，OMP over anchor）** | **11.0 → 2.9 ms** |
| **ATTN_PSA（C2PSA，仅 yolo11n）** | **18.9 → 5.5 ms** |

⇒ 非 conv 合计 **44 → 17 ms（2.6×）**；e2e **12.3 → 14.0×**。

### 2.5 两条「数量级」路线都被数据证否

| 路线 | 判据 | 结果 |
|---|---|---|
| **原生 int8 直接卷积**（免 im2col） | 纯 MAC 吞吐须 ≥ 现状真实 GEMM 已达的 15.2 GMAC/s/核 | `vdotq` 1 位置 **23.62** / 4 位置 ILP **93.58** / `vmlal_s8` 直接卷积 **7.98**（理想化 14.38）GMAC/s ⇒ **ALU 上限低于现状已达** ⇒ 6.5–11.7× 劣势**不可能回收** |
| **换激活量化粒度消 F32 gather** | J-CPU-2 检测等价 | per-tensor **0/6 PASS**、per-channel **2/6 PASS** ⇒ 数值不可行 |

**ISA 硬约束（本篇最值得记的一条）**：`vdotq_s32` 要求 **K 维 16 字节连续**；卷积的 K=(C·KH·KW) 天然不连续 ⇒ **必须靠 im2col 的 gather 制造连续性**。免 im2col 的「位置向量化」只能用 `vmlal_s8`（每 8 积需 `vmovl`+`vaddq` 拓宽进 int32，int16 累加 2 项即溢出）——**用不了 dotprod 的单指令 16-MAC**。

## 3. 最终成绩与那个「反超」

### 3.1 本引擎两条路径 vs 官方

| 路径 | yolov8n cats | yolov8n room | 相对官方（16.05 ms） |
|---|---|---|---|
| **官方 RKNN**（`rknn_run`，NPU，n=20） | **16.05**（min 13.86） | 同 | 1.0× |
| 我们 **CPU**（image_total，dotprod） | **142.4** | **132.8** | **8.9× / 8.3×** |
| 我们 **NPU**（im2col→GEMM 提交） | 232.3 | 219.1 | 14.5× / 13.7× |

### 3.2 反超：CPU（142 ms）比自家 NPU（232 ms）快 1.6×

因为 NPU 路径走「**CPU im2col(78 ms) + 371 次提交/回读累加**」，而 CPU dotprod 把全部算力压在 A76 上、**无提交/回读开销**。

⇒ **就「追官方」而言，当前最优路径是 CPU 而非 NPU**：CPU 把差距压到 **~8.9×**，优于引擎 NPU 路径的 ~14.5×。

### 3.3 换算与地板

- CPU 相对**自身标量基线**：**~14×**（e2e 2422/2273 → 172.9/161.9 ms）。
- 与官方 16.05 ms 差距 **~8.4–8.9×**，已 **conv-bound（CONV 占 88%）**；GEMM 4 核扩展仅 3.26×、im2col 为 gather 下界 ⇒ 达该设计**实际地板**。

## 4. 本篇要点回收

| 教学点 | 内容 |
|---|---|
| **转置取向** | 迁就硬件编码约束（M=OC、N=P），不是数学 |
| 先冻结论 | Phase 0 就判定「追平 16ms 不可达」，避免无限投入 |
| 时序上界 | 原生卷积标定三轮用尽 ⇒ 按纪律回退 M2 |
| **重定性**（`VLLM_NPU_TIMING`） | 发现「NPU 只占 36 ms，91% 在 CPU」⇒ 优化方向整个改变 |
| 显式回退 | J4：`[NPU] fallback conv ...` + 计数，绝不静默 |
| **ISA 是硬约束** | `vdotq` 要 K 连续 ⇒ 免 im2col 只能 `vmlal_s8`（6.5–11.7× 劣势） |
| 寄存器/ILP 平衡 | 4-way 是 A76 平衡点；8-way 退化（与向量/Laya 篇同一堵墙） |
| **证否即回退** | P-分块、8-way ILP、`memset`、BO cacheable、多核提交、原生卷积、两条数量级路线——**七次以上** |
| 位级 vs 容差 | 并行化/预计算/BO 复用全部 md5 6/6；只有量化类才走 J-CPU-2 容差 |
| **旧结论会被推翻** | 「NPU 更快」在本路径上被实测推翻（CPU 反超）；口径变了结论就变 |

## 5. 系列结语

三个模型，三种形态，一个方法论：

1. **先冻结判据**（含归零上界）——避免在解释不了差距的方向上投入；
2. **用探针/伸缩实验判别瓶颈**——口算与反算会骗你（向量篇的「14.1 GB/s」、Laya 篇的「attention 非瓶颈」、YOLO 篇的「NPU 内核慢」都是被实测推翻的口算）；
3. **位级门与容差门不互换**，改变数值就登记；
4. **证否即回退**，负结果与正结果同等重要；
5. **回退透明**，绝不静默降级；
6. **承认地板**——「没有更多空间」也是一个完整、可交付的结论。

三条最终曲线：向量 **−1.2%**（已到地板）、Laya **60.2×**、YOLO CPU **14×**（且反超自家 NPU）。它们的价值不只在数字，更在**每一步都能追溯到一行实测数据**。
